# 分级总表月度实发数量与退货率自动更新设计

## 目标

将现有固定日期、固定 `Y/AA` 列的ERP同步脚本改造成长期运行的月度更新工具。脚本按最近的每月1日或15日节点自动选择业务日期窗口，全量更新分级总表中的实发数量与退货率，滚动维护月份列、同期销量公式和变化情况公式，并安全替换同一个主工作簿。

## 已确认的业务规则

### 运行节点

- 实际运行日在每月1日至14日时，执行当月1日任务。
- 实际运行日在每月15日至月底时，执行当月15日任务。
- 同一节点可以重复运行；重复运行只刷新数据和报告，不重复新增列。

### 实发数量

- 1日任务查询上月1日至上月最后一天，写入上月实发列。
- 1日任务不插入列，并将 `8月实发（8.15）` 之类的阶段表头标准化为 `8月实发`。
- 15日任务查询本月1日至14日，写入本月阶段实发列。
- 15日任务首次运行时插入月份列；本月表头使用 `9月实发（9.15）` 形式。

### 退货率

- 1日任务查询上上月15日至上月15日。
- 15日任务查询上月1日至上月最后一天。
- 退货率表头必须显示实际查询范围，例如 `退货率（7.15-8.15）` 或 `退货率（8.1-8.31）`。

实发数量和退货率的日期窗口不同，因此每次运行必须分别请求ERP，不能从同一个日期范围的响应同时取两个字段。

## 工作表滚动布局

脚本通过表头文字定位列，不再依赖固定列字母。需要识别的核心表头包括：

- 月份实发：同时兼容 `8月实发`、`8月实发（8.15）`、现有半角括号、尾部空格及 `实销/实发销量` 等历史写法。
- `同期销量`
- `变化情况`
- 以 `退货率` 开头的表头

15日首次运行时，在当前“同期销量”列之前插入一个新列。以9月15日为例，插入前的核心布局为：

```text
7月实发 | 同期销量 | 8月实发 | 变化情况 | 退货率
```

插入并刷新后为：

```text
8月实发 | 同期销量 | 9月实发（9.15） | 变化情况 | 退货率
```

具体操作顺序为：

1. 插入列，使同期销量、本月实发、变化情况、退货率及其右侧业务列整体右移一列。
2. 将已完成的上月实发值和样式复制到新插入的上月列。
3. 将右移后的本月实发列改为新月份阶段列并写入本月1日至14日数据。
4. 隐藏上上月及更早的月份实发列，只保留“上月实发｜同期销量｜本月实发｜变化情况｜退货率”作为主要展示区。
5. 更新筛选范围、命名范围、列定义、条件格式、公式引用和其他受列插入影响的A1引用。

当前工作簿没有位于插入点右侧的绘图锚点，但实现仍需检测相关绘图部件；如果未来出现右侧锚点，应同步右移，避免图片与业务列错位。

## 公式规则

同期销量使用上月整月实发折算14天：

```text
同期销量 = 上月实发 ÷ 上月自然日数 × 14
```

分母按上月实际天数取28、29、30或31，并正确处理闰年。

变化情况使用：

```text
本月阶段实发 - 同期销量
```

显示文字沿用现有“某月增加N件／某月减少N件／持平”样式，月份替换为当前月份。公式写入所有有货号的数据行，并保留现有单元格样式和条件格式。工作簿计算属性设置为自动计算并在打开时执行完整重算，避免保留旧公式缓存。

1日任务只把阶段实发更新为整月值并删除表头日期后缀，不插入月份列。下一个15日节点才执行下一次列滚动。

## ERP查询与全量匹配

每次运行执行以下数据流：

1. 根据运行节点生成实发窗口和退货率窗口。
2. 分别请求ERP“销售主题报表/按款”接口并保存带日期窗口的快照。
3. 遍历分级总表所有带货号的行。
4. 分别在两份ERP结果中按规范化货号匹配；同货号存在多条记录时使用商品名称消歧。
5. 精确匹配和 `sku_aliases.json` 中已确认的别名自动写入。
6. 模糊匹配、无法消歧或ERP缺失的普通货号保留原值并写入人工审核报告。

`target_skus.txt` 不再作为写入过滤器，而作为关键货号校验清单。清单内每个货号必须同时满足：

- 存在于工作表；
- 在实发查询结果中确定匹配；
- 在退货率查询结果中确定匹配。

任一关键货号失败时，生成报告但不替换主文件。普通货号失败不阻断其他确定匹配项。

## 幂等性

脚本使用“节点日期＋月份表头”判断工作簿是否已完成结构变更：

- 15日周期已存在本月阶段表头时，不再插列，只刷新数值、公式、退货率和报告。
- 1日周期阶段后缀已经删除时，不重复改名，只刷新整月数值、退货率和报告。
- 不以输出文件是否存在或上次进程状态判断结构变更。

因此9月15日至月底任意日期重复执行，都只能得到同一种列结构；数据值可随ERP订单、退款和售后状态变化而刷新。

## 文件保存与恢复

配置改为指定一个长期使用的主工作簿，不再要求用户维护输入、输出链。

保存流程：

1. 在主文件同目录创建唯一临时文件。
2. 以现有快速ZIP补丁方式生成完整临时XLSX，不用普通Excel库重写图片和媒体。
3. 对临时文件执行ZIP CRC、目标工作表、关键表头、月份唯一性、核心公式、关键货号及输出摘要校验。
4. 验证成功后将现有主文件移动为固定 `.bak`。
5. 将临时文件原子替换为主文件。
6. 如果替换阶段失败，立即用 `.bak` 恢复主文件。
7. 始终只保留最近一个成功版本的 `.bak`。

如果主工作簿正被WPS或Excel锁定，脚本应明确报错并保留原文件，不尝试破坏性覆盖。

## 报告和快照

每次运行创建按节点区分的报告与ERP快照，至少包含：

- 实际运行时间和归属节点；
- 实发查询起止日期；
- 退货率查询起止日期；
- 新增或复用的月份列；
- 表头、隐藏列和公式更新数量；
- 每行实发旧值与新值；
- 每行退货率旧值与新值；
- 模糊匹配、歧义和ERP缺失货号；
- `target_skus.txt` 关键货号校验结果；
- 主文件、临时文件和备份处理结果。

快照与差异比较必须按字段所属的查询窗口分开保存，避免将不同窗口的实发和退货率错误地视为同一份历史快照。

## 错误处理

以下情况不得替换主文件：

- ERP Cookie失效、接口请求或分页失败；
- 两个日期窗口中的任一个未完整返回；
- 核心表头缺失、重复或顺序不符合预期；
- 本月结构状态无法唯一判断；
- 关键货号校验失败；
- 临时XLSX结构、CRC或公式校验失败；
- 主文件被锁定或原子替换失败。

失败时保留报告、快照和临时诊断信息，但主文件维持运行前状态。

## 测试与验收

### 单元测试

- 1日、2日至14日、15日、16日至月底的节点归属。
- 跨月、跨年、2月和闰年的两套日期窗口。
- 28、29、30和31天月份的同期销量公式。
- 半角/全角括号、尾部空格及历史实发表头识别。
- 15日首次运行插列和同周期重复运行不插列。
- 1日删除阶段后缀但不插列。
- 实发与退货率分别使用对应ERP响应。
- 全量匹配、别名匹配、歧义审核和关键货号阻断。

### XML集成测试

- 列字母、单元格引用、公式、条件格式、自动筛选和定义名称随插列正确右移。
- 上上月及更早月份隐藏，上月、同期和本月保持可见。
- 样式、百分比格式和变化情况条件格式保留。
- 工作簿开启自动完整重算。
- 同一15日节点连续运行两次，第二次输出不新增列。

### 真实工作簿离线验收

- 使用保存的两份ERP JSON在约270MB真实工作簿副本上运行。
- 验证输出ZIP全部成员CRC、工作表行数、图片和媒体成员数量不变。
- 抽查 `target_skus.txt` 中货号的实发、退货率、同期公式和变化公式。
- 在WPS中打开输出，确认主要展示顺序、隐藏列、筛选、公式重算和图片显示正常。
- 验证 `.bak` 能恢复到运行前版本。

## 非目标

- 不自动修改人工诊断、优化情况、补货意见等其他业务列。
- 不自动接受新的模糊货号映射；仍需人工确认后加入别名文件。
- 不安装或依赖WPS/Excel进行后台自动化。
- 不保留无限数量的工作簿备份；只保留一个最近成功版本。
